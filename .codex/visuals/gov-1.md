# Track B, agent L: labs for docs/governance

All labs sit on `VizPanel` with `useDarkViz()`, colours from `palette.ts`, a `table` prop, no external dependencies and no
randomness at render time. Numbers that Python produced are embedded as integers (counts), and the lab divides them, so the
printed number and the lab default are the same number.

## AttackSurfaceLab (chapter 01, red-teaming LLM systems)

- Data: 32 rows, one per subset of five defence layers (bit 0 input filter, bit 1 output filter, bit 2 tool policy, bit 3
  delimit untrusted data, bit 4 no secrets in the prompt). Each row holds the number of successful attacks out of 80
  (8 seeded attack variants x 10 trials) for six categories: direct injection, jailbreak, exfiltration, indirect injection,
  tool abuse, knowledge poisoning. Generated by running the chapter's harness (`rt1_chapter.py`) over all 32 subsets.
- Controls: five checkboxes (layers), a Reset button.
- Drawn: six horizontal bars, success rate per category for the chosen layers, with a tick for the no-defence rate; overall
  rate and the count of attacks that land.
- Default (no layers): 361 of 480 attacks land, overall 0.752; per category 57, 57, 65, 68, 50, 64 of 80. All five layers:
  29 of 480, overall 0.060; remaining 24 (direct injection), 3 (tool abuse), 2 (knowledge poisoning).
- Table: category, count of 80, rate, rate with no defences.
- Keyboard: native checkboxes and buttons.

## FairnessThresholdLab (chapter 02, fairness testing in practice)

- Data: the chapter's first block (seed 7, 20,000 synthetic applicants, logistic regression, test half of 10,000 rows). For each
  of the two groups the counts of positives and negatives whose score is at or above each threshold 0.00, 0.02, ..., 1.00,
  plus the group's positives P and negatives N (A: 1,861 and 4,095; B: 675 and 3,369). Generated by `fa_lab_data.py`.
- Controls: threshold for group A and for group B (range 0 to 1, step 0.02), a checkbox to keep them locked together, and four
  preset buttons that set group B's threshold to the nearest grid value matching group A's selection rate, true positive
  rate, false positive rate or precision.
- Drawn: left, the two groups' ROC curves with a marker at each chosen threshold; right, bars for selection rate, TPR, FPR and
  precision per group with the gaps written out.
- Default (both thresholds 0.30): group A selection 0.352, TPR 0.579, FPR 0.248, precision 0.515; group B 0.275, 0.575, 0.215,
  0.349. Demographic parity gap 0.077 (rounded from the chapter's 0.0765), equalised odds gap 0.033.
- Table: the four metrics per group and the gap.
- Keyboard: native range inputs, checkbox and buttons.

## PrivacyBudgetLab (chapter 03, privacy, PII and differential privacy)

- Model: the Laplace mechanism on a counting query with sensitivity 1. Closed-form densities, so no randomness and no embedded
  data. Density of the released value for the true count and for the count with one person added: (epsilon / 2) exp(-epsilon |x - c|).
- Controls: epsilon (slider over the grid 0.01, 0.02, 0.05, 0.1, 0.2, 0.3, 0.5, 0.75, 1, 1.5, 2, 3, 5, 10; default 0.5), probe output (slider -8 to +8
  counts from the true count, default 3, step 1), number of repeated releases k (slider 1 to 100, default 1), total budget
  (select 1, 2, 5, 10; default 1).
- Drawn: the two shifted densities, a vertical marker at the probe output, the density ratio at that output against the bound
  e^epsilon, the noise scale 1/epsilon, the expected absolute error (equal to the scale), the total epsilon spent for k
  releases (k x epsilon) and whether it exceeds the budget.
- Default (epsilon 0.5, probe 3, k 1): noise scale 2.0, ratio 0.607 at output +3 (the chapter prints 0.607 for output true
  count + 3 and the bound 1.649), total epsilon 0.5 of 1.
- Table: epsilon 0.01, 0.1, 0.5, 1, 5 with noise scale and expected absolute error (the chapter's simulation prints
  100.98, 9.95, 1.99, 1.00, 0.20 for the empirical error).
- Keyboard: native range inputs and select.

## RiskTierLab (chapter 04, regulation and model documentation)

- Data: the chapter's second block, a teaching triage of eleven example systems, each with one or more rows of tier, article
  and the date from which that obligation applies under Regulation (EU) 2024/1689 as amended by Regulation (EU) 2026/1744.
  Generated by running the chapter code (`rg_lab_data.json`). A teaching aid, not legal advice.
- Controls: system (select of the eleven), reference date (select: 2026-10-02, 2026-12-02, 2027-12-02, 2028-08-02).
- Drawn: a timeline of the verified application dates (2 Feb 2025, 2 Aug 2025, 2 Aug 2026, 2 Dec 2026, 2 Dec 2027,
  2 Aug 2028) with a marker at the reference date; below it the tier rows for the chosen system with their dates and whether each
  is in application at the reference date or how many days remain.
- Default (CV screening tool, 2026-10-02): high-risk (Annex III point 4), Article 6(2) and Chapter III Sections 1 to 3, applies
  from 2027-12-02, in 426 days. The chapter prints the same row.
- Table: all eleven systems at the chosen reference date.
- Keyboard: native selects.

## IncidentTimelineLab (chapter 05, AI incident response)

- Model: closed-form exposure model, no randomness. Harm window = detect + acknowledge + decide + contain minutes; harmful
  responses = rate per minute x harm window. Containment minutes are parameters of the chapter's model, not measurements:
  kill switch 2, rollback 15, hotfix 120.
- Controls: detection delay (slider 1 to 240 min, default 47), acknowledge (1 to 60, default 5), decide (1 to 120, default
  18), containment method (select, default rollback), harmful responses per minute (slider 1 to 60, default 12).
- Drawn: a horizontal bar split into four phases coloured by phase, with minute labels, then the harm window and the exposure
  count; a second thin bar shows the same incident with a kill switch for comparison.
- Default: 47, 5, 18 and 15 minutes, harm window 85 minutes, 1,020 harmful responses; with a kill switch 72 minutes and 864
  responses; with a hotfix 190 minutes and 2,280. All printed by the chapter's third block.
- Table: phase, minutes, share of the window.
- Keyboard: native range inputs and select.
